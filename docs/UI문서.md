# 코코비즈(코스트코 자동화 프로그램) — UI 문서

> 작성일: 2026-10-25 · 대상: 이 프로그램의 화면을 고치거나 새로 만드는 개발자·운영자
> 함께 보는 문서: [설계문서](설계문서.md) · [개발문서](개발문서.md)

## 1. 화면이 두 벌이다

| 구분 | 주소 | 기술 | 상태 |
|---|---|---|---|
| **Streamlit 앱** (기존·PC 중심) | `cocobiz.shop/app` | Streamlit, `app.py` + `pages_lib/*.py` | 모든 기능이 있음. 느리고 재시작 시 화면이 리셋됨 |
| **Next.js 앱** (신규·모바일+관리자 넓은 화면) | `cocobiz.shop/m` | Next.js 14 App Router, `mobile/` | 일부 기능부터 이전 중 |
| (참고) 수익계산 React 베타 | `cocobiz.shop/calc` | Next 정적 export, `web/` | 수익 계산 화면에서 링크 |

**전환 방향:** Streamlit에는 응급 수정만 하고, 새 화면과 무거운 화면(영수증 정산, 정산·청구, 트렌드)은 Next.js(`/m`)로 옮긴다. 두 앱은 같은 로그인 세션(`auth.db sessions`)을 공유하므로 Streamlit에서 `/m/...?sid=토큰` 링크로 넘어가면 다시 로그인하지 않는다.

- Streamlit: `ui_theme.py`의 `COLORS`, `CHART_COLORS`, `inject_global_css()`, `_inject_design_system()`
- Next.js: `mobile/tailwind.config.ts`의 `primary`, `gray` 스케일, `fontFamily.sans`

### 2.2 표현 규칙
- **금액**은 천 단위 콤마, 원 단위 정수. 마이너스는 빨강.
- **상태 배지**: 주력=빨강, 시도=파랑, 관찰=회색(트렌드) / 청구 상태 draft·billed·paid.
- **메시지**는 이모지 접두어 + 한 줄 설명: `✅ 저장됨`, `⚠️ 확인 필요`, `❌ 오류`.
- **되돌리기 어려운 동작**(삭제·초기화·정산 교체)은 반드시 확인 단계를 둔다.
  - Streamlit: 두 번 누르기(“⚠️ 정말 삭제? (한번 더)”) 또는 확인 체크박스.
  - Next.js: `window.confirm()`.
- **돈이 오가는 화면**은 “영수증 금액 = 청구 + 재고 입고 + …” 같은 **대조 등식**을 화면에 보여 준다(영수증 정산 돈 흐름 패널, 정산·청구 등식).

### 2.3 Streamlit 공통 요소 (`ui_theme.py`, `app.py`)
- 헬퍼: `hero_section`, `section_header`, `kpi_card`, `chart_card_open/close`, `quick_action_buttons`, `info_pill`
- 사이드바 244px 고정(768px 이상), 모바일은 상단 “☰ 메뉴” 펼침
- 모든 페이지 상단(설정 제외)에 **🤖 AI 질문 칸** (`pages_lib/_ask_ai.py`)
- 저장 안 한 변경 경고 모달 `st.dialog("⚠️ 저장하지 않은 변경")` — 현재 주문 수집 화면만 사용
- 표 편집은 `st.data_editor`(영수증 정산 15곳, 재고 5곳, 정산·청구 5곳 등)
- 캐시 헬퍼는 TTL 30~180초, 쓰기 후 `invalidate_data_cache()`로 비움

### 3.5 영수증 정산 화면 상세 (가장 복잡한 화면)
진행 순서대로 위에서 아래로 배치한다.

1. **정산일 · 그날 발송건** — 당일 발송건은 **전부** 보여 준다(매칭 안 된 것 포함, 관리자가 수동 정리). 이전 날짜 이월분은 `rs_show_carry` 체크 시에만.
2. **누락 발송건 올리기** — CJ 엑셀에 빠진 건 추가.
3. **영수증 업로드** — 💾 영수증 저장 / 📂 불러오기.
4. **정산 매칭** — 기준 선택 후 매칭 실행.
5. **💰 사용자별 정산표** → 💾 저장 · ✅ 정산 요청(추가/교체).
6. **📊 한눈에** 탭: 🧾 영수증 / 📦 재고 / 🛒 온라인 / ❓ 없음 / 📥 출고 안 됨 / ✍️ 직접 지정.
7. **배치 상세**(data_editor) — 처리 열: `— 그대로 —` / ✅ 영수증가 청구 / 📦 재고 출고 / ✂️ 끊기. 영수증 수량보다 많이 나간 건(초과분)을 표시하고 관리자 확인을 받는다.
8. **미분류(영수증 없는 출고) 패널** — 재고 주인 자동 추천(`_auto_owner`)과 **자동 금액**(본인 재고=미청구분, 타인 재고=할인가+1,000원, 정상가 구매=구입가).
9. **💰 돈 흐름 패널** — 영수증 금액 = 청구 + 재고 입고 + 대기 … 대조.
10. **📦 재고 현황** [배정 대기 \| 사용자별 재고], 반품, 이력, 🧨 전체 초기화(체크 확인).

> 관리자가 고른 처리(✅/📦/✂️)는 `settle_draft`에 저장된다. 서버가 재시작돼도 선택이 남는다.

## 4. Next.js 화면 목록 (`/m`)

| 경로 | 화면 | 권한 | 주요 내용 · 호출 API |
|---|---|---|---|
| `/` | 진입 | – | 쿠키로 `/dashboard` 또는 `/login` 이동 |
| `/login` | 로그인 | – | 아이디·비번·로그인 유지 → `POST /m/api/auth/login` (httpOnly `sid` 쿠키) |
| `/dashboard` | 대시보드 | 사용자 | 알림 카드, 오늘 KPI(매출·수익·주문·수량), 7일 추이, 주/월 비교 — `/m/api/dashboard/kpi` |
| `/orders` · `/orders/[date]` | 주문 내역 | 사용자 | 날짜 목록 → 날짜별 주문, 장보기 링크 |

### 4.1 API 호출 두 갈래
- **Next 자체 API**(`/m/api/...`, SQLite 직접 읽기): `fetch(withBase('/api/...'))`. `withBase()`를 빠뜨리면 `/m`이 안 붙어 404가 난다.
- **파이썬 FastAPI**(`/api/...`): `lib/client/billing.ts`의 `call()`을 쓴다. 일부러 `withBase`를 쓰지 않는다. 토큰은 쿠키 `sid` + `?sid=`(sessionStorage `billing_sid`) → Bearer.

### 4.2 알려진 UI 문제 (수정 대상)
- `lib/client/products.ts`의 `fetchProducts`, `lib/client/settlement.ts`의 GET이 `withBase`를 빠뜨림 → `/m`에서 404 가능.
- `MoreMenu`가 관리자 메뉴를 일반 사용자에게도 보여 준다(설명에 “(관리자)”만 표시). 서버에서 403으로 막히지만 메뉴에서 숨겨야 한다.
- 페이지 단위 관리자 검사가 없다(서버 API만 막음).

## 5. Streamlit ↔ Next.js 이전 현황

| Streamlit 화면 | Next.js | 남은 차이 |
|---|---|---|
| 홈 | `/dashboard` | 달력·게시판·베스트 없음 |
| 일일 주문 수집 | `/orders*`, `/shopping/*` | 카페24 주문 조회 없음 |
| 송장번호 | `/tracking` | 자동 발송처리·합배송 없음 |
| 수익 계산 | `/profit*` | 월별 분석 없음 |
| 정산 매칭 | `/settlement` | 쿠팡·AI 브리핑 없음 |
| 제품 DB | `/products` | 대부분의 관리 기능 없음 |
| 순위 체크 | `/rank*` | 거의 동일 |
| 영수증 등록 | `/receipt` | 동일 |
| 설정 | `/settings` | 일부 섹션만 |
| 관리자 | `/admin` | 회원 관리·공유 DB·라이선스·AI 사용량 없음 |
| 영수증 정산 | `/receipt-settle` | 1~4차 완료(발송 파일·영수증 올리기·매칭·배치 상세·미분류 처리·남은 품목 배정·정산 요청). 기존 화면에만 남은 것: 열 매핑 직접 수정, 보낸 업체 분류 관리, 재고·반품·이력·전체 초기화 패널 |
| 정산·청구 | `/billing` | 월별 정리·정산 이력 없음 |
| — | `/trends` | Next 전용 |

**아직 Next.js에 없는 화면:** 마진계산기, 내 구매내역 정산, 내 영수증 정산, 세무회계, 재고 관리, 네이버 등록, 카페24, 자동화, 구매가·매핑, 포장 관리, 설정 가이드, 회원가입·라이선스 화면.

**권장 이전 순서**(느림·리셋 피해가 큰 순서): 영수증 정산 2~3단계 → 재고 관리 → 정산·청구 나머지 → 내 구매내역 정산 → 송장 자동 발송처리 → 나머지.

## 6. 새 화면을 만들 때 체크리스트
1. 관리자 화면이면 FastAPI `require_admin`으로 막고, 메뉴에서도 관리자에게만 보이게 한다.
2. 표가 넓으면 `AppShell`의 WIDE 목록에 경로를 추가한다.
3. 돈이 바뀌는 버튼은 확인창 + 결과 토스트 + 대조 등식을 넣는다.
4. 사용자가 고른 값(처리 선택 등)은 세션이 아니라 **DB 초안 테이블**에 저장한다. 재시작에도 남아야 한다.
5. 숫자 계산은 화면이 아니라 파이썬 서비스(`*_service.py`)에 두고 Streamlit과 Next가 같은 함수를 쓴다.
6. 표 맨 위에 “무엇을 하는 화면인지” 한 줄 설명을 둔다. 기능이 많아 헷갈린다는 피드백이 있었다.
